# Production Kelly Shadow Tournament — Immutable Intake Contract (PKST-V1)

**Authority:** Production `production_funnel_picks` in football project `sincere-balance`. **Consumers:** Production Kelly Tournament only. **Mode:** read-only shadow; not a bookmaker, not Production operator state, not Research/KellyLab. **Effective:** forward-only from configured `PRODUCTION_KELLY_START_AT`. **Maintainer:** QuantBet operator. **Schema contract version:** `PKST-V1`.

## 1. Invariants — must always hold
1. Production picks, not Research picks, are the ONLY eligible input universe. Source is the persisted `production_funnel_picks` table, filtered by immutable `cloned_at >= PRODUCTION_KELLY_START_AT`. Never call `matching_bucket_ids`, reapply today’s selected buckets, reinterpret current policy, or derive admissions from research signals.
2. Exactly one canonical candidate per `production_funnel_picks.pick_id`. Keep every registered candidate in the audit (including entries later marked SKIPPED by operator); strategies may choose NO_BET when the probability, cash, timing or eligibility makes an executable bet impossible. Never silently drop invalid candidates: classify, count, expose.
3. Preserve the Production clone’s `pick_id`, `source_universe`, `source_pick_id`, `cloned_at`, `kickoff_at`, `odds`, `model_probability`, `market_probability`, `intake_contract_version`, `matched_bucket_ids`, market, selection, bookmaker and fixture. The current Production bucket list must have **no** influence over historical rows.
4. Never substitute the current price or current model probability for immutable intake fields. Strategy probability must be the frozen Production model probability; missing/invalid probability => NO_BET, not fallback to Research or artificial 50%. “Calibrated” strategies are forbidden without a frozen Production-native calibrated probability.
5. Strategies share **identical** candidate rows in the **identical** chronological ordering. Differences in placed bets are permitted only because Kelly stakes, bankroll reservation, cap, rounding, model edge or strategy rule differ. All strategy simulations begin with RSD 30,000 independently. Historical Production stake and operator PLAYED flag do not become simulated stake.
6. First simulate placement at `cloned_at`; reject retroactive placement after kickoff or when result was already known; reserve open stakes immediately. Release and pay out only on defensible source settlement evidence and timestamp, never merely from visible latest result without an acquisition time. Settlement earlier than kickoff (except confirmed manual VOID) => quarantine as PENDING and audit.
7. WIN profit = round(stake × (odds − 1)); LOSS = −stake; VOID = 0; PENDING = no realised P/L. Stakes are 10 RSD rounded and always cash/cap bounded. Bankroll reconciliation: available + reserved = initial + realised P/L; total open stakes equals reserved; negative balances are forbidden.
8. Source facts and operator decisions may never be written by the tournament. The tournament must run SELECT-only on the football PostgreSQL database. Forbidden: INSERT, UPDATE, DELETE, DDL, migrations, settlement writes, source picks writes, API-football calls, strategy-driven Production intake changes.
9. Every report must expose: observed time, cohort start, row count, policy version breakdown, settled and pending counts, strategy names/rules, per-strategy P/L, ROI, return, drawdown, reserved cash, cash denials, invalid input count, quarantined results and source errors.
10. Failure mode is CLOSED: missing source DB, invalid start timestamp, unsupported settlement, inconsistent ledger or incomplete scan => HTTP 503 / visibly provisional. Never silently switch to KellyLab/Research or report healthy empty results from a source failure.

## 2. Boundaries and settlement semantics
- Production funnel admission is NOT the same as an actual bookmaker execution. PENDING/PLAYED/SKIPPED operator states are observational metadata only. The shadow tournament evaluates the **full admitted Production cohort**, including operator-SKIPPED clones; this tests sizing conditional on Production intake, not realized operator trading.
- Source settlements originate from the same underlying Research, GoalLab and CornerLab tables used by the Production dashboard; the clone's original decision is immutable, but latest settlement facts can be corrected.
- **V1 limitation:** a query-time reconstruction from latest known settlement is **provisional** if a correction/reversal event lacks complete original history. Explicitly flag it; never claim point-in-time live-executed accounting. Immutable persisted stake allocations and a confirmed append-only settlement event ledger are required before advertising this as production-grade causal forward shadow accounting. Until then call the output **provisional cash-constrained replay**.
- Research manual VOID is handled as VOID. A manual CORRECTION/REVERSAL without an independently verifiable full cash timeline is quarantined rather than treated as a normal historical cash release. Quarantine does not alter source records.
- Source data can settle after kickoff, in which case only the acquisition timestamp releases reserves. Missing settlement timestamp => PENDING.
- If Production starts accepting a new source universe or market without a verifiable outcome mapping, it enters the cohort but stays PENDING with audit reason; do not infer a result.

## 3. Experiment design
- `PRODUCTION_KELLY_START_AT` is an explicit UTC instant and is never changed without starting a named new cohort. No cherry-picked backfill into the primary ranking.
- The 17 v1 strategies use the SAME frozen Production **model** probability: Flat 300 RSD, Flat 1% equity, and ¼, ½ and full Kelly with risk caps 1%, 2%, 3%, 5%, 10% (15 combinations). Models, caps and rounding must be clear in the UI and JSON. These intentionally differ from KellyLab's Research-calibrated strategies; do not mislabel as direct equivalence.
- One cohort for all policies; additionally segment P/L by `intake_contract_version` and report when strategy comparisons span changed bucket policies.
- No auto-promotion to real-money. Before selecting a winner require mature settled sample, out-of-sample validation, confidence intervals, max drawdown and settlement audit quality.

## 4. Release checks and drift detection
- Existing `/kelly-tournament`, `/kelly-tournament.json`, `/settlement-history` and KellyLab source stay unchanged. New routes are `/production-kelly-tournament` and `/production-kelly-tournament.json`; optionally `/production-kelly-tournament/health`.
- Invariant tests: different current bucket config cannot mutate already-cloned candidate set; same one-time source input yields deterministic replay; no duplicate candidate; stop at kickoff; preserve model probability and odds; segregated bankroll per strategy; reservations and releases correctly timed; WIN/LOSS/VOID/REVERSED and missing evidence; empty newly started cohort is valid; DB failure is not zero picks; all 17 consume same candidate IDs.
- Source live read **must** use DB reference variable `DATABASE_URL=${{Postgres.DATABASE_URL}}` set on the tournament service. For hard least privilege, replace with a dedicated SELECT-only role before real-money decisions.
- Changes to this contract require explicit new version, documented migration and test evidence. No silent contract drift, deployment of unrelated football services, or rewriting archived history.

## 5. Operational definition of done
(a) Stored version-controlled contract; (b) live isolated new tournament route on existing low-cost Railway Function; (c) actual DB read works; (d) active routes existing unaffected; (e) JSON shape and invariants verified against Production rows; (f) if validation fails, report blocked/degraded truthfully. Do not claim (c)–(e) from deployment success alone.
